# SimpleURL

> 轻量、流畅、好用的高级短链接系统。粘贴链接，回车即得。

自托管、单文件部署、自带访问统计与二维码。技术栈：**FastAPI + SQLAlchemy + SQLite + 原生前端**，无构建步骤。

## 特性

- **一键生成** — 粘贴长链接回车即得短码，也可自定义短码
- **安全可靠** — URL 白名单校验、内网地址拦截、短码去重、防刷创建限额
- **访问统计** — 总点击 / 独立访客 / 30 天趋势图 / 来源 Top，按 IP 哈希脱敏
- **二维码** — 每条链接自动生成 PNG 二维码
- **标签管理** — 标签下拉直接用库里的真实标签，前后台都能按标签筛，状态筛选与多字段搜索并存
- **链接控制** — 随时停用 / 启用 / 删除 / 编辑，支持设置或清除过期时间
- **创建前校验** — 自定义短码边打边查占用（大小写不敏感），目标地址重复时直接给出现成短码
- **批量操作** — 勾选多条一次性启用 / 停用 / 续期 / 打标签 / 删除，翻页仍保留已选（上限 500 条）
- **回收站** — 删除先进回收站留 30 天，误删能捞回来；期间短码仍占用，恢复后原样可用，到期自动清理
- **操作留痕** — 创建、修改、删除、改设置、导入都记一条，谁在什么时候动了哪条一目了然
- **数据导出** — 按当前筛选一键导出 CSV，Excel 直接打开不乱码
- **社交平台防洪** — 微信 / QQ / 微博等内置浏览器逐平台放行、静默或拦截，带中转页与来源分布
- **自动取标题** — 创建时真去抓目标页 `<title>`（重定向逐跳过 SSRF 闸），抓不到用 URL 兜底，并记录来源：抓取 / 兜底 / 手填
- **设备统计** — 桌面端 / 移动端 / 机器人来源一目了然
- **可选私密** — 配一个 `ACCESS_TOKEN` 就能把整个站点锁起来
- **安全加固** — CSP、CSRF 防护、Argon2id 口令哈希、登录限速、可信代理
- **到期提醒** — 列表与仪表盘都标出「还剩几天」，7 天内到期可一键筛出，也能一键推到通知通道
- **库备份** — 后台一键下载整个 SQLite 库文件，账号 / 配置 / 点击明细一起带走
- **运行状态** — 后台一屏看库体积 / 待结算 / 丢了多少点击 / 部署自检告警
- **点击对账** — 没计入点击的访问按原因分账：UA 屏蔽 / 平台拦截 / 放行不计数 / 超出配额，配额用尽会亮告警
- **二维码工坊** — 160~1024px 六档尺寸、PNG / SVG 双格式、可带品牌图标（错误纠正提到 H），矢量印刷不糊
- **回执自助** — 凭回执能改目标 / 标题 / 标签 / 过期时间、能停用、能续期、能删除，不用等管理员
- **救回失效链接** — 过期或停用的短码，别人看到「打不开」，创建者看到「续期并重新启用」按钮
- **回执找回** — 创建时留一个线索（邮箱或自述），丢了回执凭它换一张新的；只重签最近一条，1 小时 3 次
- **CSV 导入** — 把自己导出的表格、Excel 另存的 CSV 直接灌进来，中英文表头都认，没表头按「哪列像链接」猜
- **告警外推** — Webhook / 邮件 / Bark 三通道，部署自检与配额告警出现时自动推一条，同类 1 小时内不重复
- **精致界面** — 深色玻璃质感、响应式、无框架依赖、极光动效
- **无背景 Logo** — 提供 SVG 矢量与 16~512px PNG，深浅底色通用

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动
./run.sh                     # 默认 http://localhost:8000
```

或使用 Docker：

```bash
docker compose up -d         # 首次需构建
```

首次启动自动建表（SQLite），无需任何额外配置。

### 创建前校验

两条都是「提前把话说清楚」，不是新门槛——提交时后端照样再校验一遍。

- `GET /api/codes/{code}/available` — 短码能不能用。长度、字符集、保留字、大小写不敏感的重名
  都会给出具体原因。当前请求没有创建权时（admin 模式下的访客、弱口令收权）一律回「可以用」，
  否则这个接口就是个免费的短码库扫描器。
- `GET /api/duplicate?target=` — 这个地址是不是已经收过了。比对时忽略协议、末尾斜杠与 `#` 片段，
  所以 `http://a.com/x`、`https://a.com/x/`、`https://a.com/x#top` 会认成同一条；
  查询串不同则算不同页面。结果按「能用且点击多」排序，直接复制复用即可。
  只给管理员：返回的是别人建的短码，开放出去等于给链接库开后门。

创建示例：

```bash
curl -X POST http://localhost:8000/api/links \
  -H 'Content-Type: application/json' \
  -d '{"target":"https://example.com/very/long/url","code":"my-link","tags":["文档"]}'
```

## 时间与过期

库里一律存 UTC，页面上按本地时区显示，中间那一步换算必须只有一处。

过期时间的坑值得单独写一段：浏览器 `datetime-local` 给的是「用户眼里的时间」，
形如 `2026-12-31T23:59`，它**不带时区**。以前后端 `replace(tzinfo=utc)` 直接当 UTC 收，
于是国内用户填「12 月 31 日 23:59 过期」，实际却在北京时间 1 月 1 日 07:59 才失效——
设的人很笃定，看结果的人也很笃定，只是差了 8 小时。

现在两边都说清楚自己的口径：

- 前端把本地时间补上偏移再发（`2026-12-31T23:59:00+08:00`）
- 后端遇到不带时区的输入，按进程时区解释（`TZ` 优先，其次系统时区）
- 带时区的输入按原样换算

想改服务器认的时区，设 `TZ=Asia/Shanghai` 即可；统计按天分桶、每日配额、
「今天」的口径都跟着它走。

## 访问模式

站点级开关，决定外部访客能干什么，后台「设置 → 访问模式」随时可改。

| 模式 | 访客能创建 | 访客能看链接库 / 详情 / 导出 / 统计 | 访客能打开短链 | 自己刚建的那条 |
| --- | --- | --- | --- | --- |
| `open` 开放外部可使用 | 可以 | 不可以（仅管理员） | 可以 | 凭回执链接可看 |
| `admin` 仅管理员可使用 | 需登录 | 不可以（仅管理员） | 可以 | 无 |

两条硬规则：

- **跳转永远对所有人开放。** 短链的命根子是「点得开」，模式只管「能不能建」。
- **链接库与统计永远只给管理员。** 开放模式开的是「建」，不是「看别人的」——
  一份完整的链接清单摊在公网上，等于把所有人建的短链都曝出来。

未配置 `ADMIN_TOKEN` 时自动按 `open` 运行，避免配错把站点锁死在门外；
配了但短于 12 位则按「仅管理员」收权（见下方「口令强度」）。

### 回执链接：访客也能管自己那条

开放模式下访客建完链接，响应里会多一条 **回执链接**（`/s/<短码>?t=<领取码>`）。
凭它能看到这一条的详情、统计与二维码，也能**自己动手打理这一条**：

| 能做什么 | 入口 | 说明 |
| --- | --- | --- |
| 改目标 / 标题 / 标签 / 过期时间 | 统计页「这条链接是你建的」面板 | 填错一个字不用重开一条 |
| 续期 | 同上，或刚建完的结果卡片 | `days` 默认 30，从「此刻」与「原到期时间」取更晚的那个往后推 |
| 停用 / 重新启用 | 同上 | 停用后别人打不开，创建者凭回执仍进得来 |
| 删除 | 同上 | 立刻失效，回执一并作废 |

几条边界，刻意没放开：

- 短码不让改。改掉之后别人手上那条链接会变成孤儿
- 回执只开**自己那一扇门**：拿 A 的回执去碰 B 一律 401
- 管理员的 `PATCH /api/links/{code}` 仍能改全部字段；`self` 接口是给访客的那一份

- 领取码只返回一次，服务端只存哈希；它**不是第二套账号**，只是一张回执
- 管理员自己创建时不发领取码（用不着），也无需回执即可访问 `self` 接口
- 回执会一并带进统计页里那张二维码的地址，不然那张图会被挡在门外

### 链接失效了怎么办

短链最安静的翻车方式是「发出去半年后突然打不开」——到期了，或者自己停了。
现在同一个 URL 对两种人给两种页面：

- **路人**：一句「该短链接已过期 / 已停用」，加一个回首页的按钮
- **创建者（带有效回执）**：多一块面板，能看到目标地址、累计点击、到期时间，
  并当场「续期并重新启用」，续完自动跳到目标地址

续期从「此刻」与「原到期时间」里取更晚的那个再往后推，所以「还剩 3 天」的链接
续 30 天不会把这 3 天吞掉。

```bash
# 仅管理员可使用
ACCESS_MODE=admin ADMIN_TOKEN=$(openssl rand -hex 24) ./run.sh
```

## 社交平台防洪（微信 / QQ 等）

短链在国内最常见的传播路径就是微信、QQ 里点开，而这两家客户端的内置浏览器
带着能认出来的 UA（`MicroMessenger`、`wxwork`、`QQ/`、`MQQBrowser`…）。
这类流量既是主要来源，也是刷量与投诉的源头，所以给了逐平台的三档策略：

| 策略 | 跳转 | 计数 | 适用 |
| --- | --- | --- | --- |
| 放行并计数 `allow` | ✅ | ✅ | 默认，正常分享 |
| 放行不计数 `silent` | ✅ | ❌ | 怀疑被刷量，又不想影响真实用户 |
| 拦截并提示 `block` | ❌ 返回中转页 | ❌（留痕） | 外链被举报、想在站外先拦一道 |

后台「防洪 / UA 屏蔽 → 社交平台防洪」按平台逐个选，改完即时生效，不用重启。
认得出的平台：微信、企业微信、QQ、微博、支付宝、钉钉、抖音、小红书。
企业微信的 UA 里同样带 `MicroMessenger`，所以先认企业微信，别把同事当外人。

被拦下的访问不会白屏，给一张带品牌的中转页：提示语可自定义，附「继续访问」
「复制链接」和 iOS/安卓都适用的三步指引——微信里外链被墙时，用户最需要的
其实是「怎么绕过去」，不是一句 403。

**这些不是靠 `User-Agent` 一刀切**：

- UA 认不出时还会看 `Referer`，从 `mp.weixin.qq.com` 点进来同样算微信来源
- 只认客户端的特征标记，不封整个 `Android` / `iPhone`，普通手机浏览器照常
- 拦截只发生在跳转入口，统计页、二维码、API 不受影响
- 被拦的访问落一条 `blocked` 事件：不计入点击，但仪表盘看得到拦了多少

统计侧多两处：链接统计页与后台都有「来源平台」分布（近 14 天 / 全部），
微信里点开多少、QQ 里点开多少、被拦多少，一屏看清。后台另有「拦截留痕」，
最近被拦的访问按平台列出来（短码、平台、时间、UA 摘要），只留痕不计数。

### 配额的两处硬账

- **每日配额按自然日重置**：`click_daily_limit` 走的是「今天的第几次」，
  不是滚动 24 小时。滚动窗口会让昨晚刷满的人在今天早上继续被关在门外。
- **限速器是原子的**：先读后写要加锁，否则并发下实际放行量能到上限的好几倍，
  热链接上尤其明显。没有客户端地址时按同一个「unknown」算配额，不是直接放行。

### 来源判定顺序

1. UA 特征标记（企业微信先于微信，它的 UA 也带 `MicroMessenger`）
2. `Referer` 里的平台域名（`mp.weixin.qq.com`、`url.cn`、`qzone.qq.com`…）
3. 都认不出就当其它来源

`Referer` 这步是必要的：微信里用「复制链接」再打开、或从聊天窗口外链进来，
UA 常常是干净的 Safari / Chrome，只看 UA 会漏掉一大半真实来源。

> 提示：UA 是客户端自报的，能伪造。这里的定位是「挡住大量真实的内置浏览器
> 流量并给真实用户一条出路」，不是对抗刻意伪装的攻击者——那种要靠限速和配额。

## 安全

### 传输与会话

- 全站响应统一带 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 等安全头
- 页面下发带 nonce 的 CSP：脚本只放行 `'self'` 与带 nonce 的内联块，挡住注入的脚本
- 管理会话是 HMAC-SHA256 签名的 HttpOnly Cookie，`SameSite=Lax`，服务端不存会话；改 `SECRET_KEY` 等于全站踢下线
- 后台登录按 IP 限速（默认 5 分钟 10 次），配额用尽后连正确口令也挡

### CSRF

所有写请求都要在 `X-CSRF-Token` 头里回带页面下发的令牌，与 cookie 比对一致才放行。攻击者能诱导浏览器带 cookie，但读不到 cookie 内容，所以伪造不出这个头。`/yourls-api` 兼容接口与静态资源不参与校验。

### 口令哈希

`ADMIN_TOKEN` 支持直接填哈希值而不必存明文，算法优先 Argon2id（m=19MiB / t=2 / p=1），缺依赖时自动退到 PBKDF2-HMAC-SHA256 60 万次迭代。哈希编码带算法名前缀，参数低于当前标准时会提示升级。

```bash
python -c "from app.core.crypto import hash_secret; print(hash_secret('your-password'))"
```

### 客户端 IP

默认只信任回环代理的 `X-Forwarded-For` / `X-Real-IP`。不设这道关的话，任何人都能伪造转发头把限速和每日配额绕得一干二净。上了 Nginx 就把内网网段填进 `TRUSTED_PROXIES`。

### 操作留痕

短链接最典型的事故不是宕机，是「我的链接怎么跳到别处去了」。没有留痕只能靠猜，
所以所有写操作（创建 / 修改 / 删除 / 批量 / 改设置 / 导入 / 登录）都落一条
`audit_logs`，后台「操作留痕」按时间倒序看，可按动作筛选。

只留动作与对象：操作者、短码、变更字段、时间。IP 与点击统计一样只存哈希，
日志表只保留最近 2000 条，长跑进程不能只涨不落。

### URL 校验

创建短链时挡掉带 userinfo 的地址（`https://trusted.com@evil.com` 这类钓鱼伪装）、内网 / 回环 / 链路本地 / IPv4 映射 IPv6 地址，以及非 http/https 协议。

只校验字面 IP 是不够的：`http://10.0.0.1.nip.io` 这类域名自带解析，前一秒还是「一个普通域名」，
后端一请求就摸到内网。所以域名会再看一眼解析结果，任一地址落在内网就拒收，
解析失败也按不安全处理（宁可少收一个域名，不可放行一次内网探测）。
结果缓存 `DNS_CACHE_TTL` 秒——不能长，DNS 重绑定要的正是「第一次解析是公网」。

自动取标题走的是同一条判定（`titles._is_safe_host` 直接复用 `is_public_url`），
两套规则各写一遍，早晚会有一边漏。

### 口令强度

`ADMIN_TOKEN` 短于 12 位时，访客能做的事一律收回（创建、链接库、统计全关），
只保留跳转；后台仍可登录去换口令，但「密码能猜到」不会再顺带变成「别人能当管理员」。
后台「运行状态 → 部署自检」会把这条和其它配置隐患直接列出来。

### 访问令牌

开了 `ACCESS_TOKEN` 之后，`?token=xxx` 校验通过就写进 HttpOnly Cookie，
之后刷新、翻页、看统计页里那张二维码都不用再带参数。前端门禁存的是
sessionStorage 里的明文，靠拼 query 跳转——服务端不认它，门禁就是死循环。

## 点击对账：没计入的那些访问去哪了

短链的点击数天生会和「实际点击」差一截：被 UA 黑名单挡下的、被平台策略拦下的、
放行但不计数的、以及撞上单 IP 每日配额的。以前这四种在库里只有一个 `blocked` 布尔，
后台统一显示「已拦截」——看着像一回事，处置方式却完全不同。

现在每一条没计入的访问都带 `block_reason`：

| 原因 | 含义 | 该怎么办 |
| --- | --- | --- |
| `ua` | 命中自定义 UA 黑名单 | 误伤正常用户就去改规则 |
| `social` | 被社交平台防洪拦下，返回提示页 | 想放行就把策略调成 `silent` / `allow` |
| `social_silent` | 页面正常打开了，但按策略不计数 | 只是统计口径，用户没受影响 |
| `quota` | 单 IP 每/每日配额用尽 | 配小了就调大；反代没配好会让所有人共用一份配额 |

三处都看得到：统计页的「未计入点击」、仪表盘的分账卡、运行状态的分项数字。
配额用尽占比超过一成、且绝对值超过 20 次时，运行状态会直接亮黄灯说明原因。

存储上只加了一列 `block_reason`（老库启动时自动补，见 `core/db.py`），
升级前的历史记录归到「历史未分类」，不会因为升级被算丢。

## 回收站：删除留一手

短链最疼的误操作不是「建错了」，是「手滑删掉一条已经发出去半年的」。
以前 `DELETE` 就是 `DELETE`，`click_events` 跟着级联走，谁都救不回来。

现在删除只是把它挪进回收站：

| 动作 | 入口 | 说明 |
| --- | --- | --- |
| 删除（单条 / 批量） | 链接列表、`DELETE /api/links/{code}` | 进回收站，`enabled` 一并置停 |
| 恢复 | 后台「回收站」、`POST /api/trash/{code}/restore` | 原样回来，链接立刻能跳 |
| 彻底删除 | 后台「回收站」、`DELETE /api/trash/{code}` | 不可撤销，点击明细一起没 |
| 清空 | `POST /api/trash/empty` | 一次清干净 |

几条刻意的边界：

- **回收站里的短码仍算占用**。放开了，恢复时就会跟新建的那条撞车，
  而撞车的那一刻你没法替用户选谁是对的
- **回收站只留 30 天**，每天随点击明细清理一起跑一遍。留一年等于没删，
  `links` 表会一直长
- **访客自助删除是一次性的**。开放模式下访客凭回执删自己那条，不给回收站——
  没有管理员可恢复，留着只占地方
- 回收站单独计数，写在「运行状态」里：删了怎么库还这么大，得有个答案

## 二维码工坊

短码是给人点的，二维码是给机器扫的——贴海报、印名片、放 PPT，需求完全不同。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `size` | 160 / 240 / 320 / 480 / 640 / 800 / 1024 | 就近取档，按目标边长反推每格像素，不会糊 |
| `fmt` | `png` / `svg` | SVG 是矢量，放多大都不糊，适合印刷 |
| `logo` | `0` / `1` | 带品牌图标时错误纠正开到 H，中间挖掉 20% 照样扫得出来 |
| `download` | `0` / `1` | 1 时按附件下载，文件名带短码 |

后台「二维码 → 二维码工坊」是同一套参数的界面版，预览和下载走同一个 URL
——省得「预览是一个、下下来是另一个」这种经典错位。

```bash
curl -b cookie.txt 'http://localhost:8000/api/qr/docs?size=800&fmt=svg&logo=1' -o docs.svg
```

## 回执找回：线索机制

回执（领取码）服务端只存哈希，丢了就真没了，而开放模式下又没有管理员可问。
以前只能「拿旧回执换新回执」，可也常常连旧的都不在手上了。

现在创建时可以顺手留一个**线索**（邮箱，或一句只有你记得的自述），它做成的是
「弱恢复」而不是「账号」：

- 线索本身也存哈希，不落明文
- 反查必须重新提供同一个线索，且同一 IP 1 小时只有 3 次机会
- **只重签最近一条**链接的回执，不是「你名下全部」

也就是说：知道你的邮箱，最多碰运气看到你最近建的那一条。这比「丢了彻底没救」
好，也比「凭邮箱列出全部短链」安全得多。线索默认保留 30 天，每个线索只留最近 5 条。

管理员创建的链接不发回执（用不着），「找回」入口只在首页，访客点「回执丢了？」展开。

## 导入：YOURLS 与 CSV

两条路，一条认转储、一条认表格：

| 来源 | 入口 | 认什么 |
| --- | --- | --- |
| YOURLS | 后台「数据迁移」 | `INSERT INTO yourls_url ...` 的 SQL 转储、JSON 导出 |
| CSV | 后台「数据迁移 → 从 CSV 清单导入」 | 本系统导出的 CSV、Excel 另存的 CSV |

CSV 的表头中英文都认（`短码`/`code`、`目标地址`/`url`/`target`、`标题`/`title`、
`标签`/`tags`、`点击`/`clicks`、`过期时间`/`expires_at`）；一个都不认识时就按
「哪一列以 http 开头」猜，纯文本清单也能灌。分隔符自动识别逗号 / 制表符 / 分号。

共同行为：短码冲突自动换一个可用码（`renamed` 计数），同一份文件里重复的目标地址
跳过（`skipped` 计数），其余计数在 `imported` / `failed` 里。CSV 额外把标题、标签、
点击数、过期时间一起带进来。

## 到期提醒：别让链接静静死掉

短链最安静的失效方式是「发出去半年后突然打不开」。仪表盘早就标了「还剩几天」，
可那得有人主动点开才看得见——而这恰恰是没人看的时候发生的事。

所以「即将过期」那张卡上多了一个按钮：把 7 天内到期的链接打包推到所有配好的通道。

```bash
curl -X POST -b cookie.txt 'http://localhost:8000/api/admin/notify/expiring?days=7'
```

推出去的内容是人话，不是 JSON——收件人是在手机上看：

```
以下 3 条将在 7 天内到期：

· /docs   12-31 23:59  剩余 3 天  https://example.com/docs
· /promo  01-02 10:00  剩余 5 天  https://example.com/campaign
```

想让它每天自动跑一次，一条 cron 就够（接口要求管理员会话，所以要么带 cookie，
要么走 `X-Api-Key` + 管理员会话）。没有即将到期的链接时接口直接短路返回
`count: 0`，不会去骚扰通道。

## 通知：告警别再等人点开

部署自检、配额告警、到期提醒这些以前只写在后台「运行状态」页里——得有人主动点开
才看得见。真出事那天，通常谁都没在看。

| 通道 | 需要填 | 说明 |
| --- | --- | --- |
| Webhook | 接收地址、（可选）校验密钥 | JSON POST，`{title, text, level, site, time}`；密钥走 `X-SimpleURL-Secret` 头 |
| 邮件 | SMTP 服务器、账号、授权码、收件人 | 465 端口填 `starttls=0` 走 SSL，587 保持 `1` 走 STARTTLS |
| Bark | `https://api.day.app/你的Key` | iOS 推送，`warn` 级用 timeSensitive |

规则：

- 总开关在后台「通知」页，也可以 `NOTIFY_ENABLED=true` 起手打开
- 后台每 5 分钟看一次告警，出现新的就推；**同类告警在冷却期内不重复**
  （冷却键取告警文本本身，换了内容就值得再发一次）。冷却时长在「通知」页可改，
  默认 3600 秒，填 `0` 表示每次都发；环境变量 `NOTIFY_COOLDOWN` 是出厂值
- webhook 地址走与创建短链同一套 SSRF 校验，不能被用来探内网
- 发送在后台线程里跑，一个 8 秒超时的 webhook 不会拖住保存设置
- 每次投递留一条结果（成功 / 失败原因）在通道卡片上，不靠翻日志

```bash
NOTIFY_ENABLED=true NOTIFY_WEBHOOK_URL=https://example.com/hook ./run.sh
```

## Logo

位于 `app/static/logo/`，全部**纯透明背景、无底板**，深浅底色都能直接用：

- `icon.svg` / `icon-{16,32,48,64,96,128,180,192,256,512}.png` — 主图标
- `favicon.svg` / `../favicon.ico` — 站点图标（画布收窄，小尺寸更清楚）
- `icon-mono.svg` — 单色版，用 `currentColor` 即可换色
- `logo-horizontal.svg` — 图标 + 字标横版（字标跟 `currentColor` 走）

造型是一条从右上绕回、再把去路折成箭头的折返线，讲的就是「长链接被绕短」。
渐变沿对角线铺，折返处自然衔接深蓝 → 紫 → 品红。

重新生成（需要 `cairosvg` + `Pillow`）：

```bash
python scripts/gen_logo.py
```


## 说明

- 默认 SQLite，日活十万以内完全够用；量大了切 Postgres 只需改 `DATABASE_URL`
- 统计数据仅存 IP 的 SHA-256 前 32 位，不落明文 IP
- 停用 / 过期 / 不存在的短码都会返回友好页面，不会裸奔报错
- 删除（含批量）先进回收站留 30 天，期间短码仍占用；到期随每日清理任务自动彻底删除
- 延迟计数是内存缓冲，进程退出时会强制结算一次；极端崩溃可能丢最近几秒的点击
- 跳转链路上的防洪策略（频率上限 / 社交开关 / 平台策略 / UA 规则）合并成 3 秒快照，
  减少热链接上的重复查询；后台一保存立刻失效，改完马上生效
- 被 UA 屏蔽的访问仍会跳转，也会留一条带 `blocked` 标记的记录，只是不计入点击数
- 自动取标题会请求目标站，已做 SSRF 防护（内网/回环/链路本地地址一律不抓；
  重定向逐跳校验，防止公网地址 302 到内网元数据接口）。它在独立线程里跑，
  不会撞上「事件循环已在运行」；超时上限由 `FETCH_TITLE_TIMEOUT` 控制，
  不想等出网就在创建请求里带 `fetch_title: false`
- **站内静态资源允许被外站引用**：短链站的核心用途就是贴到别处，微信 / QQ 抓预览卡片、
  博客里嵌二维码，都是跨站引用。默认 `STATIC_CROSS_ORIGIN=true`，
  只对 `/static/`、图标和 `/api/qr/` 放开 `Cross-Origin-Resource-Policy`；
  页面本身仍是 `same-origin` + `X-Frame-Options: DENY`，防点击劫持不受影响
